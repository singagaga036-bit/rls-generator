# rls-generator

Генератор названий РЛС СССР/РФ с подробными справками и ТТХ.

Живой сайт: https://singagaga036-bit.github.io/rls-generator/

## Что внутри
- `index.html` — страница сайта
- `style.css` — оформление (тёмный экран РМО)
- `app.js` — логика: вращающийся луч, цели на радаре и карточка станции
- `data-*.js` — база станций по темам (наземные, ЗРК, корабельные, бортовые и т.д.)

## Шаблон станции
Новая запись вписывается в подходящий `data-*.js` перед закрывающей скобкой `);`:

    {
      name: 'Название станции',
      year: 'Год',
      nato: 'Имя в НАТО',
      desc: 'Описание — можно в 2–3 предложения.',
      ttx: [
        ['Дальность', '300 км'],
        ['Шасси', 'ЗиЛ-131']
      ]
    },

Поля `nato` и `ttx` необязательные: если их нет, карточка сама их скроет.
Счётчик «В базе станций» обновится автоматически.

## ИНСТРУКЦИЯ ДЛЯ ИИ
Работай на скорость и экономию токенов. Правила обязательны.

Чтение:
1. Структуру узнавай деревом: `GET /git/trees/main?recursive=1`. Файлы просто так не открывай.
2. Файл читай один раз и только тот, который правишь: `GET /contents/{path}` с заголовком `Accept: application/vnd.github.raw+json` — придёт обычный текст, без base64. Формат записей задан шаблоном выше — `data-*.js` изучать целиком не нужно.
3. GitHub REST API (скилл `github_rest`) — единственный инструмент. Без веб-поиска. Независимые запросы отправляй параллельно.

Запись:
4. Правка данных = одна операция. Несколько станций копи в одну правку файла (один GET + одна запись), а не по одной.
5. Пиши без base64: `POST /git/blobs` (`content` — обычный текст, `encoding: "utf-8"`) → `POST /git/trees` (`base_tree` + новый blob вместо файла) → `POST /git/commits` (`parents` = HEAD) → `PATCH /git/refs/heads/main`.
6. Правки точечные: только нужный файл и участок. Без переписывания файлов целиком, без новых файлов и лишней документации. README трогай лишь при изменении структуры проекта или формата данных.
7. Данные без дублей: перед добавлением проверь, нет ли станции уже. Лимиты: `desc` — до 3 предложений, `ttx` — до 6 строк, поля — только по шаблону.

Ответ и проверка:
8. Коммит — одно изменение, сообщение коротко по-русски («Добавлена станция X»).
9. Проверка — код ответа API (200/201). Повторно файлы не открывать.
10. Ответ пользователю — итог в 2–5 строк. Код и диффы в чат не разворачивать. Объяснения простыми словами.

Лишний запрос, лишний файл, лишний абзац — перерасход. Их быть не должно.
